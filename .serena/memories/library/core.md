# Library Architecture and Workflow

`library/`: builds `@penpot/library`; JS-facing in-memory Penpot file builder and `.penpot` ZIP exporter. Separate from main app runtime.

## Layout and commands

- Source: `library/src-ts/` (TypeScript, ESM); tests: `library/test/` (product contract) and `library/test-ts/` (unit); config: `esbuild.config.mjs`, `package.json`, `tsconfig.json` (noEmit). No Clojure toolchain remains.
- From `library/`: build `pnpm run build` (esbuild bundles `src-ts/index.ts` into `target/library/penpot.js` plus map); watch `pnpm run watch`; tests `pnpm run test` (builds, then `node --test` on `test/**/*.test.js` and `test-ts/**/*.test.ts` via Node type stripping); `pnpm run watch:test` for the loop. CI runs `./scripts/test`.
- `node --test` uses default discovery: never leave compiled copies of tests under `target/` or each case is counted twice.
- The package version is owned by `package.json`; the build injects it through esbuild `define` as `__PENPOT_LIBRARY_VERSION__`. Code run straight from sources (unit tests) falls back to `0.0.0-test`.
- When changing file-format construction or export behavior in `common/`, consider whether `@penpot/library` should be tested because it constructs Penpot files outside the app UI.
- Cross-cutting testing principles and anti-patterns: `mem:testing`.

## JS API and builder state

- The JS build context is a plain object that closes over a `BuilderState` and replaces it on every mutation; `getInternalState` returns the JS view. The exporter bypasses it through `RAW_STATE` (`state.ts`).
- The API follows the CLJS surface: same method names (`addFile`, `addPage`, `addRect`, `addBool`, `addTokensLib`, ...), same getters (`currentFileId`, `currentPageId`, `lastId`). Failures become `BuilderError` with `type`/`code`/`hint`, enumerable `cause` and `explain` getters.
- `createBuildContext(options)` accepts an optional `referer`, later written into the export manifest.
- The builder is stateful: call `addFile` before `addPage`. `addPage` resets the frame/group stack to the root and clears page-local naming state when the page closes.
- `addBoard` and `addGroup` push onto the parent stack; matching close calls pop it. `closeGroup` requires at least one child and recalculates group geometry. Masked groups use the first child as mask and copy its geometry.
- `commitShape` emits an `add-obj` change with `ignoreTouched: true`, using the current parent, frame, and page from the stack.
- Layer names are uniqued per current page; duplicate names get generated suffixes.
- `addBool` converts an existing group into a bool shape and updates style/content/geometry through one `mod-obj` change rather than adding a new object.
- Media blobs are stored separately from file-media metadata; `addFileMedia` requires a `Blob` and fails with `validation`/`invalid-media` otherwise.

## Export package

- `.penpot` ZIPs include `manifest.json`, file/page/shape JSON, components/colors/typographies/tokens, media metadata, and media object blobs.
- Path/bool shape `:content` is converted to vectors before JSON encoding.
- File export intentionally includes only selected top-level attrs plus data options; color export removes `:file-id` and drops empty paths.
- Manifest type is `penpot/export-files`, version 1, generated by `penpot-library/<package version>`, with optional referer and file relations.
- Export generation is sequential and lazy: delayed JSON/blob work is computed only as each zip entry is written, and the progress callback receives `{total,item,path}` after each entry.
- The library has compatibility defaults for features/migrations in the common builder; do not assume it always exports with the newest app-default migrations/features.
